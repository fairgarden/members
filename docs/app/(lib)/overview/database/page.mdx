# Database

Drizzle, over `pg`, the same as the id service: any Postgres, tables prefixed
`members_`, and an embedded PGlite in `.data/members` (port 54320) when there
is no database URL.

```bash
pnpm db:generate --name add-thing
pnpm db:migrate
pnpm db:rollback [--steps N | --to TAG]
pnpm db:status
```

Each migration's rollback is the hand-written `<tag>.down.sql` beside it. A
real database is migrated by the build that deploys it — `pnpm migrate`, which
is `fg-dist migrate --build` and runs after `next build` — or by hand with
`pnpm db:migrate`, never at start-up. In a monolith, its build migrates this
app along with the others it mounts, each recorded in its own journal
(`members_migrations` here), so they can share one database.
